# 产研飞书文档撰写

创建符合团队规范的产研飞书文档（需求文档/技术方案/设计文档/项目复盘）。

## 输入

- 文档类型: $ARGUMENTS[0] (需求文档/技术方案/设计文档/项目复盘)
- 主题: $ARGUMENTS[1] (文档主题或功能名称)
- 其他参数: $ARGUMENTS

## 核心规范

### 1. 标题格式

- ❌ 禁止使用 emoji
- ✅ 使用数字编号：1., 1.1., 1.1.1.（最多三级）
- ✅ 点后需要空格以触发飞书自动编号

```markdown
# 1. 概述
## 1.1. 背景
### 1.1.1. 业务背景
```

### 2. 版本历史

每份文档开头必须包含版本历史表格：

```markdown
| 版本号 | 修改时间 | 修改人 | 变更说明 |
|--------|----------|--------|----------|
| v0.1   | YYYY-MM-DD | <mention-user id="ou_xxx"/> | 初稿 |
```

版本号规则：v0.1 初稿 → v0.2/v0.3 修订 → v1.0 评审通过 → v1.1/v1.2 后续变更

### 3. 阶段规划

**严格禁止时间预估**，用阶段名称和交付物描述：

```markdown
### 第一阶段：核心功能
- 目标：实现基础数据查询能力
- 交付物：核心 API 接口、基础前端页面
- 依赖：无
```

### 4. 团队术语

**角色:**
- RD: 研发（前端/后端/采集/大数据/Agent 工程师）
- PM: 产品经理
- UX: 设计师
- PoC: 负责人（Point of Contact）

**产品线:** 出海匠、Trenz、AllGoods

**业务板块:** 数据洞察、内容制作、社媒管理、客资管家、建站精灵、Agent

**PoC 标注:** 使用 `<mention-user id="ou_xxx"/>` 标签（先用 `search-user` 获取 open_id）

- **技术方案**: 查看 [references/templates.md](references/templates.md) 的"技术方案模板"

所有模板遵循相同的核心规范：版本历史表格、数字编号标题、无时间预估的阶段规划、规范的术语使用。

## 工作流程

1. **加载工具**: 使用 ToolSearch 加载 feishu-mcp 工具
2. **确认需求**: 询问文档类型、主题、产品线、业务板块、参与角色
3. **生成内容**: 按模板创建，确保版本历史、标题编号、术语规范、阶段规划
4. **飞书操作**:
   - 创建: `mcp__feishu-mcp__create-doc`
   - 更新: `mcp__feishu-mcp__update-doc`（同步更新版本历史）
   - 搜索: `mcp__feishu-mcp__search-doc`

   **错误处理**:
   - **工具未加载**:
     - 错误信息: `Tool not found`
     - 解决方案: 使用 `ToolSearch` 搜索并加载 `feishu-mcp` 工具
     - 命令: `ToolSearch query="feishu"`
   - **用户搜索失败**:
     - 可能原因: 用户名拼写错误、用户不在飞书系统中
     - 解决方案:
       1. 确认用户名拼写（注意大小写）
       2. 尝试使用邮箱搜索
       3. 询问用户确认飞书账号
   - **文档创建失败**:
     - 可能原因: 权限不足、网络问题、API 限流
     - 解决方案:
       1. 检查飞书权限设置
       2. 验证网络连接
       3. 如遇限流，等待 1-2 分钟后重试
       4. 查看详细错误信息，向用户说明具体问题
   - **文档更新失败**:
     - 可能原因: 文档已删除、无编辑权限、版本冲突
     - 解决方案:
       1. 确认文档仍然存在
       2. 检查当前用户的编辑权限
       3. 如有版本冲突，先获取最新版本再更新

5. **质量检查**:
   - [ ] 版本历史表格完整
   - [ ] 标题数字编号，无 emoji，最多三级
   - [ ] 阶段规划无时间预估
   - [ ] 角色术语正确（RD/PM/UX/PoC）
   - [ ] 产品线和板块名称正确
   - [ ] PoC 使用 `<mention-user id="ou_xxx"/>` 格式
   - [ ] RD 明确类型（前端/后端等）
6. **输出结果**: 提供文档链接、概要、检查结果、后续建议

## 示例对比

## 🎯 需求背景

## 注意事项

1. **飞书工具加载**: 使用前先用 ToolSearch 加载 feishu-mcp 工具
2. **版本历史**: 每次更新文档必须在版本历史表格中新增一行
3. **术语一致性**: 全文使用统一的角色缩写和产品名称
4. **阶段描述**: 重点描述目标和交付物，绝对不要写时间
5. **PoC 标注**: 禁止直接写 `@姓名`，必须先用 `search-user` 获取 open_id，再用 `<mention-user id="ou_xxx"/>` 标签
6. **RD 类型**: 技术方案中务必区分前端/后端/采集等不同类型的 RD
7. **文档完整性**: 所有章节都要填写，不要留空
8. **参考现有文档**: 创建前可先搜索类似文档作为参考
